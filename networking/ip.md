# IP

IP stands for Internet Protocol and it is the network layer communications protocol (OSI model) that is responsible for delivering packets from the source host to the destination host based on IP addresses.

## IPv4

IPv4 addresses is a 32-bit number, expressed as four octets (8-bit) in decimal format (0-255) divided by periods (`.`):

```bash
192.168.178.3
```

It it divided into 2 parts: the network prefix and the host number. The number of bits of the network prefix is variable (CIDR). What divides the network prefix from the host number is the **network mask**, a binary mask that indicates how many bits belong to the network segment and how many to the host segment. The network masks can be represented either in CIDR notation (`/24`) or as four 8-bit octets in decimal format (`255.255.255.0`). This netmask sets 24 bits for the network and 8 for the host, which means 256 possible hosts. From this number, 2 hosts need to be subtracted, because they are reserved to the **network address** (lowest possible address) and the **broadcast address**.

```bash
[root@localhost sshd_config.d]$ ip -4 a show enp0s8
2: enp0s8: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc fq_codel state UP group default qlen 1000
    altname enx0800270dd57d
    inet 10.0.2.15/24 brd 10.0.2.255 scope global dynamic noprefixroute enp0s8
       valid_lft 43544sec preferred_lft 43544sec
```

This example shows the IPv4 configuration of `enp0s8` (Ethernet interface):
- device IP address: `10.0.2.15`
- netmask: `/24` (`255.255.255.0`)
- network address: `10.0.2.0`
- broadcast address: `10.0.2.255`

Network packets travel from host to host in a subnet and through **routers** from network to network. Every host has a **routing table** which determines the network interface to use to send packets to particular networks.

```bash
[root@localhost sshd_config.d]$ ip route
default via 10.0.2.2 dev enp0s8 proto dhcp src 10.0.2.15 metric 100 
10.0.2.0/24 dev enp0s8 proto kernel scope link src 10.0.2.15 metric 100 
172.17.0.0/16 dev docker0 proto kernel scope link src 172.17.0.1 linkdown 
```

The routing table has 3 entries:
- use `enp0s8` to send packets with any destination (`default`: `0.0.0.0`) to `10.0.2.2` (router). This is assigned by `dhcp`.
- use `enp0s8` to send packets with destination `10.0.2.0/24`
- use `docker0` to send packets with destination `172.17.0.0/16`

Entries are matched by longest prefix, which means that a packet to `10.0.2.66` would be sent with the second entry.

IPv4 addresses can be configured either dynamically via **DHCP** or through manual configuration.

## IPv6

An IPv6 number consists of 128 bits, expressed as eight groups of 4 nibbles (half a byte) expressed in hexadecimal, separated by colons (`:`):

```bash
2001:0db8:0000:0010:0000:0000:0000:0001
```

To shorten IPv6 addresses, leading zero in a group can be skipped, but at least one hexadecimal digit must be present for each group:

```bash
2001:0db8:0:10:0:0:0:1
```

Also, one or more consecutive groups of `0` can be shortened with `::` (this can be done only once in an address):

```bash
2001:0db8:0:10::1
```

> When including a port after an IPv6, enclose the IP address with square brackets:

```bash
[2001:0db8:0:10::1]:80
```

Unlike IPv4, IPv6 has a **fixed subnet mask** which is `/64`, which is used for most normal addresses. This means that 64 bits are for the host segment (interface ID).

Common IPv6 addresses:

| IPv6       | Description                      |
|------------|----------------------------------|
| `::1/128`  | `localhost`, same as `127.0.0.1` |
| `::/0`     | `default`, same as `0.0.0.0/0`   |

IPv6 can be configured manually and also dynamically via **DHCPv6** and also via **SLAAC**(Stateless Address Autoconfiguration)

## IP addresses and hostnames

Hostnames can be linked to IP addresses manually in `/etc/hosts`:

```bash
[root@localhost sshd_config.d]$ grep -v '^#' /etc/hosts
127.0.0.1   localhost localhost.localdomain localhost4 localhost4.localdomain4
::1         localhost localhost.localdomain localhost6 localhost6.localdomain6
```

This example shows that `localhost` is mapped manually to the `loopback` address both for IPv4 and IPv6.

The **DNS**(Domain Name System) network service also provides name resolution mapping. The DNS server (`nameserver`) to interact with is provided via DHCP or by creating static address settings in `/etc/resolv.conf`:

```bash
[root@localhost sshd_config.d]$ cat /etc/resolv.conf 
# Generated by NetworkManager
search tailc31b69.ts.net fritz.box
nameserver 100.100.100.100
nameserver 0.100.100.100
nameserver fd17:625c:f037:2::3
```
